# C8B — Node.js project publishing platform

C8B is an Express application with a responsive public catalogue, authentication, an Owner Control Center, project and file management, download tracking, and optional Google/Discord sign-in. The original dark UI, blue accents, and Owner **Log out** control are kept in the HTML/CSS/JavaScript frontend.

## Runtime

- Node.js 20 or newer
- npm
- SQLite (the `better-sqlite3` package is installed through npm; no separate database server is needed)

## Run locally

1. Install dependencies: `npm install`
2. Copy `.env.example` to `.env`.
3. Set a long, random `SESSION_SECRET`.
4. Create a bcrypt password hash by running `node scripts/hash-password.js` in a terminal, then put the printed hash in `OWNER_PASSWORD_HASH` in `.env`. The password must be at least 12 characters and include lowercase, uppercase, and a number.
5. Start the app: `npm start`
6. Open `http://78.154.103.47:11487`.

The SQLite database is created automatically at `database/database.sqlite` by default. Set `DATABASE_PATH` to an absolute path if your host provides a separate persistent data directory. Uploaded project files and images are stored in `uploads/`; make sure this directory persists between restarts.

## Deploy to Wispbyte

1. Create a **Node.js** server and select Node.js 20 or newer in Startup settings.
2. Upload/clone the repository root (including `package.json`, `server.js`, `database.js`, `routes/`, `middleware/`, `views/`, and `public/`). Do not upload `node_modules` or your local `.env`.
3. Set the startup command to `npm start`. The app listens on the port supplied by Wispbyte through `PORT`.
4. In Wispbyte's Startup / environment settings, configure:
   - `NODE_ENV=production`
   - `SESSION_SECRET`: a unique random value of at least 32 characters
   - `OWNER_USERNAME`: 3–24 letters, numbers, or underscores
   - `OWNER_EMAIL`: a unique email address
   - `OWNER_PASSWORD_HASH`: the bcrypt hash generated by `node scripts/hash-password.js`
   - `DATABASE_PATH=./database/database.sqlite` (or an absolute path in persistent storage)
   - `UPLOAD_MAX_MB=100` (adjust to your plan's limits)
5. Start the server and inspect the console. Visit `/health`; a healthy server returns JSON with `"status":"ok"`.

### Optional OAuth

Google and Discord login buttons are only enabled when the matching client ID and secret are configured. Set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_CALLBACK_URL`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, and `DISCORD_CALLBACK_URL` in the host environment if you want these providers. Register the exact callback URLs with each provider. Leave them unset to keep OAuth disabled.

## Data and security

- Never commit `.env`, session secrets, OAuth secrets, passwords, or real user data.
- Back up the SQLite database and the `uploads/` directory before migrating or redeploying.
- The Owner dashboard and management APIs are protected server-side; hiding a frontend control is not used as authorization.
- Wispbyte storage must be persistent for the database and uploaded files to survive server replacement/reinstallation.

## Validation

Run `npm run check` to validate the syntax of the application's JavaScript files.
